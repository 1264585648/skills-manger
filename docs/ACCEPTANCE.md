# Skills Control Center — UI 验收标准

版本：v1（2026-09-22）
适用范围：前端 `src/**`，不含 Rust 侧。

本文件是**唯一的验收口径**。每一条都必须可判定（能跑脚本验的写脚本，不能的写明人工判定方法）。
验收命令：`node scripts/audit-ui.mjs`（自动项）+ `tsc --noEmit` + `vite build` + 人工清单（交互项）。

判分：共 30 条。**全部通过才算达标**，任一条 FAIL 即整轮不通过，回到对应模块继续修。

## A. 信息架构（8 条）

| ID | 标准 | 判定方式 |
| --- | --- | --- |
| A1 | 单页 Master-Detail，无跨页跳转；不存在 Discover/Govern/WriteBack 三个页面文件 | 脚本：`src/pages/` 下文件数 == 1 |
| A2 | 切换列表选中项**不触发任何数据重新加载** | 人工：来回点 10 个 Skill，Network/日志无新请求 |
| A3 | 分发区按 **Agent 聚合**，同一 Agent 只出现一行；且**只列 PATH 里真有可执行文件的 Agent**（`installed`），不列仅目录残留的 | 脚本：渲染行数 == installed 的 Agent 数；人工复核截图 |
| A4 | 每个 Agent 行的状态三态完备：已装 / 可安装 / 已就绪（登记目录已覆盖本体） | 人工：截图核对 |
| A5 | 支持多选批量：加标签、归组、写回目标，三个动作各自可用 | 人工：勾选 3 个 Skill 逐个执行 |
| A6 | 筛选维度正交：视图筛选（全部/需处理/未治理/已失效）与「仅项目」可任意组合 | 人工：组合切换 4×2 次 |
| A7 | 异常可直达：顶部异常摘要每项可点击并落到对应列表 | 人工：点击「需处理 N」→ 列表只剩需处理项 |
| A8 | 简介失焦自动保存，无「保存」按钮 | 人工：改简介点到别处，重启应用仍在 |

### 第二轮修正 · 2026-09-22 · 「右侧只显示已安装的 Agent」

**问题**：右侧分发区列了 10 行，但本机真正装了 5 个。根因是 `detected` 判定为
「用户目录下存在 `.claude` 这类文件夹 **或** PATH 有可执行文件」——卸载后残留的空目录
也会让它为 true。GitHub Copilot / Kimi Code / OpenClaw / TRAE / Windsurf 5 个属于这种。

**修法**：把「检测」拆成两个信号（**schema v3 → v4 增量迁移**，`upgrade_v3_to_v4`，
只加列不回填行，治理数据不丢）：
- `detected`：目录存在（弱信号，保留原义）
- `installed`：PATH 里找到可执行文件（强信号，**右侧只认这个**）

迁移后本机实测：`installed=5`（Claude Code / Codex / Cursor / Gemini CLI / OpenCode）、
仅目录残留 5、未检测 5。未安装的 Agent 收进一个可勾选的折叠项，默认不显示。

复跑 `node scripts/audit-ui.mjs` → **14/14 全绿**（C1/C2/C4 含 Rust 改动后仍通过）。
