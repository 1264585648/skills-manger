HUMAN-READABLE TECHNICAL SOLUTION

桌面端 Skills 分组管理维护技术方案

把项目定义为本地优先的 Skills Control Center：先发现本机 Skill 与 Agent，再将外部副本纳入统一 Library；Group 只分类、Bundle 表达部署意图；所有写入先生成 Sync Plan，经依赖、冲突、漂移与安全检查后，由 Agent Adapter 执行。

先看结论

做一个本地优先的 Skills Control Center：统一发现和维护 Skill，一处完成分组、Bundle、版本与关系管理，再通过 Adapter 安全同步到不同 Agent；发现不等于接管，同步不等于覆盖。
一级产品结构收敛为 Skills、Groups & Bundles、Agents、Sync、Settings。
Skill 逻辑资产与 Agent 中发现的 SkillInstance 分离，Library 是唯一 canonical source。
Discovery Engine 只扫描 Adapter 给出的候选目录和用户配置源，不做全盘搜索。
部署统一走 Copy + Hash + Snapshot + Atomic Replace + Verify。
更新显式区分 Update / Local Modified / Drift / Conflict / Unmanaged / Missing。
核心产品边界

这不是新的 Agent Runtime，也不负责执行 Skill。

最大架构风险

不能假设所有 Agent 都是同一种本地目录安装方式。

核心安全原则

扫描和同步阶段绝不执行第三方 Skill 内 scripts。

Discovery ≠ Adopt；Sync ≠ Overwrite；Agent Directory ≠ Source of Truth。

Library 管 desired state；Agent 目录只是 Instance。用户直接修改目标目录时形成 Target Drift，而不是反向自动覆盖 Library。

怎么找到 Agent 与 Skill

01

Detect Agent

CLI、配置/App 目录、用户手动 Target。

02

Candidate Roots

Adapter 返回 User / Project / Plugin 等候选 Scope。

03

Scan SKILL.md

解析 metadata、资源、可执行脚本和 contentHash。

04

Resolve Identity

Source + relativePath 定来源身份，Hash 做重复辅助。

05

Unmanaged First

发现不接管，用户 Adopt 后才进入 Library。

06

Reconcile

Watcher + 启动扫描，去抖并过滤自身写入。

禁止默认扫描整个 C:\ 或整个 Home。每个 Agent Adapter 只负责自己已知的候选 roots，用户再通过 Settings 增补路径。

核心领域模型

对象职责关键规则
Skill逻辑能力资产内部 UUID；name 不是全局主键
SkillSourceGit / Local / ZIP / Agent 导入来源source type + locator + relative path
SkillInstance某 Agent/Scope 中实际存在的一份副本target + scope + physical path
Group纯分类Skill ↔ Group 多对多；删除 Group 不删除 Skill
Bundle可部署组合required / optional；部署时解析 relations
SkillRelation显式关系requires / recommends / conflicts / replaces
AgentTarget具体 Agent 安装/工作区adapter + installation/scope
Deployment受管实例记录记录 ownership 与 deployedHash
Snapshot同步前回滚基线plan + target + timestamp
Capability Matrix 是正式模型。 不同 Agent 可能只支持 discover、manual-export，或者支持 install/update/remove/verify。UI 与 Planner 必须根据 capability 决定可执行动作，不能统一写成 copySkillToAgent()。

同步更新怎么安全

01

Resolve

展开 Bundle、requires，阻断循环依赖、hard conflict 与不兼容。

02

Build Plan

生成 add / update / remove / no-op / manual-export。

03

Drift Check

目标 hash 与 deployedHash 不同就先解决 Drift。

04

Snapshot

只备份即将修改的受管内容，不删除 unmanaged。

05

Atomic Apply

staging 校验后 replace；默认 Copy + Hash。

06

Verify

重新扫描/hash，记录 Deployment；失败可回滚。

更新状态不是一个布尔值

状态判断用户动作
CleanLibrary = tracked source，Target = deployedHash无需处理
Upstream UpdateSource 变化，Library 未改Diff → 更新 Library → 重新部署
Local ModifiedLibrary 相对 Base 有修改保留 / Commit / Fork
Target DriftAgent 目标文件与 deployedHash 不一致导入目标修改 / 覆盖 / 忽略
ConflictUpstream 与 Local 都改，或 Drift 与新部署相撞三方 Diff / 手工合并 / Fork
UnmanagedAgent 中发现但没有 ownership纳入 Library / 外部管理 / 忽略
MissingDeployment 存在但目标目录被外部删除重新部署 / 解除管理
默认策略：自动扫描 Agent = ON；自动检测 Source 更新 = ON；自动下载安装更新 = OFF；自动覆盖目标 Skill = OFF。

安全边界

风险V1 规则
恶意/未知 scripts扫描、预览、同步阶段永不执行；导入页展示 scripts/ 可执行文件清单与来源
路径穿越 / symlink 逃逸canonicalize 后检查目标必须位于允许 Root；默认不追随越界 symlink
误删用户文件只删除 Deployment manifest 明确拥有的路径；unmanaged 内容不自动删除
同步中断staging + snapshot + atomic replace；记录 before/after hash
私有 Git 凭据不存普通 SQLite；使用系统凭据存储或 Git credential helper
绝不做：扫描时运行脚本；未经 ownership 判断删除目录；发现更新后自动覆盖；把某个 Agent 的路径常量散落在 Domain Core。
