# Agents 交互改造方案

状态：已实施并完成 Windows 本地验收。交付范围、测试口径及证据见 [验收报告](agents-ux-acceptance.md)。

## 1. 产品定位与目标

面向在本机使用多个 AI 编程工具的个人开发者。Agents 页负责回答：正在管理哪个 Agent、有哪些技能、如何添加或更新。

主任务为给指定 Agent 添加技能、更新已有技能和处理影响技能读取的问题。首次发现、安装目录配置、故障详情与历史恢复属于辅助任务。

体验目标是让用户无需理解 Root、实例、托管、哈希和目录优先级即可完成常用任务，同时在确认写入前知道目标范围、覆盖内容及共享影响。

默认沿用已确认的策略：用户确认后执行；技能库覆盖所选同名目标；覆盖前备份；不删除未选中技能；共享目录的影响必须明确展示。

## 2. 当前问题与改造边界

| 当前问题 | 用户影响 | 改造方向 |
| --- | --- | --- |
| 应用侧栏、Agent 列表、详情标签页和筛选并列 | 用户需要跨多层导航理解页面 | 顶部切换 Agent，主区域只展示技能列表 |
| 四项统计和扫描信息常驻 | 高频操作被低频信息分散注意力 | 统计进入管理详情，扫描状态靠近刷新入口 |
| 已选 Agent，安装时还要从全部目录选目标 | 重复判断，容易选错范围 | 沿用当前 Agent 和作用范围，必要时只确认一次位置 |
| 外部技能与技能库按名称寻找关联 | 同名不同来源可能匹配错误 | 依据部署记录或明确的来源关联匹配 |
| 选择技能后另开完整预览步骤 | 普通添加流程偏长 | 在添加面板内自动生成变更摘要 |
| 安装结果与随后刷新失败混合统计 | 用户无法判断文件是否已经写入 | 分别反馈部署结果与索引刷新结果 |
| 诊断与目录占据主标签页 | 用户频繁看到维护信息 | 问题随技能出现，配置从次级入口进入 |

本轮聚焦 Agents 页及关联的添加、更新、详情、目录管理、恢复交互。复用现有发现、规划、备份、执行和恢复能力。必要的数据补充纳入本轮；在线市场、自动后台部署、跨设备管理、Agent 原生技能启停不在本轮范围。

## 3. 页面职责

| 页面 | 核心职责 | 与本轮的连接 |
| --- | --- | --- |
| Skills | 维护技能库的内容与来源 | 可带着已选 skillIds 进入 Agents 的添加流程 |
| Agents | 管理一个 Agent 在指定范围内的技能 | 当前改版主体 |
| 工作流 | 保存技能组合与跨 Agent 分发任务 | 使用相同的选择、变更摘要和确认组件 |
| 环境更新 | 来源更新、复杂冲突与批量更新管理 | 进入时携带 Agent、范围、目标和技能上下文，避免重新选择 |
| 设置 | 全局默认值和高级配置 | Agents 中的“管理目录”提供就近入口 |

这轮不调整一级导航名称和全部页面结构。跨页入口传递上下文，确认组件复用；现有不同执行策略继续明确展示，不以统一文案掩盖策略差异。

## 4. 信息架构

### 4.1 日常主页面

```text
Claude Code [切换]                         添加技能   刷新   更多
作用范围：所有项目 [切换]

搜索技能                         全部 / 有更新 / 需处理

技能名称与一句简介                 状态              操作
代码审查                         已添加              更多
前端设计                         有更新              更新
接口测试                         需要处理            处理
```

上述名称和条目是结构示意，不是当前真实数据。

- 移除常驻第二列 Agent 列表及四项大统计，释放技能列表宽度。
- 唯一常驻主按钮为“添加技能”；存在更新时，在更新筛选或列表工具栏提供次级“更新全部”。
- 技能详情通过点击名称打开；行内只展示与当前状态相关的主操作，复制路径、打开目录等进入行内更多菜单。
- 多选后展示批量操作条；切换 Agent 或作用范围时清空勾选，避免操作对象串用。
- 主列表按真实目录身份归并重复入口。同名但不同来源的技能保留独立条目，并补充来源标识。

### 4.2 Agent 切换器

- 显示产品图标、名称；安装证据不足但存在目录时标记“仅发现配置”。
- 优先展示本机可管理的 Agent，其他受支持产品放在折叠分组中，支持搜索。
- 首次进入选择产品规则表顺序中的首个已安装 Agent；没有安装证据时选择首个存在可读目录的 Agent。
- 后续进入恢复上次的 Agent。若其已不可用，保留该上下文并提示切换，不将写入目标静默切换到其他产品。
- 全部未发现时展示发现入口与手动选择目录入口，不展示一张假装正常的空管理页。

### 4.3 作用范围与默认目标

- 对用户呈现“所有项目”和“选择项目”；选定后展示具体项目名称。应用无法证明某 IDE 当前打开的项目时，不使用“当前项目”标签。
- 列表与添加操作使用同一个范围上下文。“所有项目”指该 Agent 的全局位置，不表示同时修改多个项目目录。
- 目标优先级：用户已记住且仍有效的选择，其次是产品规则明确推荐的写入目录。
- 多个候选无法唯一确定时，就近展示一次“选择保存位置”，说明每个位置的作用范围，选定后保存偏好。
- 系统、插件只读目录不进入写入候选。共享目录即使是产品推荐默认值，也要在确认摘要中显示受影响的其他 Agent。
- 路径只有在选择存在歧义、用户展开位置详情或处理故障时完整展示。

### 4.4 次级入口

“更多”菜单固定保留“管理目录”和“操作记录”，使用稳定文字标签，避免只靠难以识别的图标。

- 技能详情抽屉：完整描述、来源、关联状态、可用位置、只读原因、内容预览和文件操作。
- 管理目录抽屉：当前 Agent 的目录、默认写入位置、项目区、扫描开关及深度。全局项目区需标明会影响多个 Agent。
- 操作记录抽屉：当前 Agent 的记录、部署结果、备份状态与恢复入口。
- 问题处理抽屉：由具体技能或非阻断提示进入，展示影响、处理动作、技术详情。

同一时刻只打开一个主抽屉，详情与添加之间采用抽屉内部切换或替换，避免弹层嵌套。

## 5. 关键用户流程

### 5.1 添加技能

1. 点击“添加技能”，打开固定在当前 Agent、作用范围下的选择抽屉。
2. 从技能库搜索并勾选；技能组合是选择方式之一，已选数量和名称持续可见。
3. 面板底部自动生成“新增 / 更新 / 覆盖 / 无变化”摘要，显示目标范围与共享影响。
4. 普通新增可在该摘要处直接确认；存在覆盖或共享影响时，必须先展开并审阅对应清单，再确认执行。
5. 执行后返回列表并定位新增或更新项，展示结果与“撤销本次变更”。失败保留选择并给出可重试入口。

预览在选择稳定后防抖 300ms；新选择立即使旧预览失效，只接受最新请求结果。预览未完成、存在阻断问题或预览已过期时禁用确认，并说明原因。

作用范围不变时不要求再次选择 Agent 或目标目录。抽屉打开后目标上下文固定；执行中可以查看进度，不能修改本次目标。执行结果与重新扫描结果分别反馈，例如“已添加 3 项，列表刷新失败，可重试刷新”。

### 5.2 本地或外部技能进入技能库

- 添加抽屉内提供“从本地导入”，技能详情提供“加入技能库”。
- 使用当前技能的来源信息，不要求用户重新在文件选择器里寻找已知路径。
- 导入前展示将进入技能库的名称和来源；需要补全跨产品必填元数据时，在同一面板收集信息，只修改暂存副本，原文件保持原样。
- 成功后继续原添加流程，并自动选中已导入技能。
- 外部同名技能不自动关联到任意 Library 记录；必须使用可信来源或让用户明确选择一次关联对象。

### 5.3 更新技能

- 单项更新：点击行内“更新”，在同一抽屉查看当前内容、技能库版本及变更摘要，确认后执行。
- 批量更新：进入“有更新”筛选，选择条目或“更新全部”，只包含当前 Agent 与当前范围内有明确关联的技能。
- 检测到目标被手动修改时，明确列为“将覆盖本地修改”；继续沿用用户确认后的技能库覆盖策略。
- 内容未变时显示“无变化”，不创建一次无意义的写入操作。

### 5.4 处理问题

| 场景 | 呈现与动作 |
| --- | --- |
| 断链或目录不可访问 | 显示受影响技能；提供打开入口位置、重新选择位置、重试 |
| YAML 或编码问题 | 展示具体文件与问题；提供定位文件和修复后重试 |
| 空目录或尚未创建的默认目录 | 正常空状态，提供添加技能；确认写入时才创建目录 |
| 部分扫描失败或取消 | 保留上次结果，标记状态尚未更新；提供重新检查 |
| 确认前目标已变化 | 提示“内容已变化，请重新确认”，保留选择并重新计算摘要 |
| 恢复时目标已再次修改 | 停止恢复并说明影响，保留当前文件和备份 |

只影响部分技能的问题不遮挡整页。基础数据完全无法读取时使用页面错误状态与重试。原始错误、路径和错误码放在展开的技术详情中。

重新选择目录用于更新扫描登记；技能内部断链通过定位入口、修复后重试处理。修复功能与扫描目录配置明确区分。

### 5.5 撤销与恢复

- 成功提示里的“撤销”针对本次完整操作，并明确涉及多少个技能。
- 提示关闭后，恢复仍可从“更多 → 操作记录”进入。
- 恢复前继续校验目标和备份；不存在恢复能力的早期记录仅展示历史，不提供不可用按钮。
- 对需要等待的恢复操作提供进行中状态，完成后局部刷新列表与记录。

## 6. 状态与数据规则

### 6.1 用户可见状态

| 状态 | 依据 | 行内操作 |
| --- | --- | --- |
| 已添加 | 文件已发现或已部署到当前范围，元数据可读取 | 查看详情 |
| 有更新 | 存在明确 Library 关联，技能库内容与最近部署内容不同；进入更新流程前检查目标现状 | 更新 |
| 需要处理 | 断链、不可读取、元数据错误等实际影响，或更新前发现需确认的本地修改 | 处理 |
| 状态待确认 | 当前检查未完成或已取消，只有历史结果 | 重新检查 |

“已添加”不等于 Agent 运行正常或已加载技能。“来源为外部”“插件只读”等作为详情或限制标签，不与主状态平级堆叠。

更新关联依据 skillId、部署记录和规范化路径，不通过名称自动推断。同名不同来源不能自动合并。读取同一物理目录的不同入口可归并展示，但必须保留关联位置，以便解释共享影响。

### 6.2 必要的数据能力

- 增加产品规则中的首选写入位置与候选分类，替换安装弹窗当前的“取第一个可写目录”行为。
- 增加技能管理视图，关联发现实例、Library、部署记录和诊断；返回可信的主状态、可执行动作及禁用原因。
- 元数据扫描继续轻量化；当前范围需要判断更新时按需计算，点击确认前必须完整校验，不把未知哈希当成“无变化”。
- 目录列表的计数、更新筛选与变更摘要使用同一组身份和范围规则。
- 安装、扫描、刷新、导入、恢复使用独立操作状态，避免一次读取让整个页面不可操作。

### 6.3 偏好与上下文

- 跨重启保存：最后选择的 Agent、作用范围、确认过的默认目录和排序方式。
- 会话内按 Agent 保存：搜索词、筛选和滚动位置。
- 多选状态不跨 Agent、范围或应用重启保存。
- 后台刷新不改变当前筛选、滚动和详情对象；对象消失时就近提示。
- 导航允许携带 agentId、projectId、skillIds 和目标上下文；写入前重新解析、校验，URL 或旧页面状态不能直接决定落盘路径。

## 7. 视觉与可访问性

- 延续现有浅色工具界面和本地图标；一级导航保持现有布局，新增空间优先给技能名称和简介。
- 正文 13–14px，主标题 24px；次要路径按需展示，按钮和列表行保持稳定尺寸。
- 使用标准下拉、菜单、复选框及带清晰提示的图标操作；只在有实际任务时出现批量操作条。
- 抽屉在宽屏保持合理阅读宽度；窄窗口扩大为覆盖内容区的面板。底部确认区固定，内容独立滚动。
- 键盘支持 Agent 选择、搜索、列表选择、抽屉打开与关闭；关闭后焦点回到原入口。
- 错误和状态同时有文字表达，不仅依赖颜色；长路径、英文技能名和高倍缩放均不能挤出容器。

## 8. 实现组织与兼容

AgentsPage 只负责当前上下文和主列表编排，拆分 AgentSelector、ScopeSelector、SkillList、SkillDetailDrawer、AddSkillsDrawer、DirectoryManagerDrawer 与 OperationHistoryDrawer。抽屉导航、操作反馈和变更摘要复用，避免在单个页面继续堆积条件分支。

现有 `get_agent_center`、`preview_agent_install`、`apply_agent_install`、`restore_agent_install` 保持兼容。补充默认目标解析、技能管理视图、偏好持久化及就近导入所需的接口。预览改为自动触发，但确认仍是唯一写入入口；已有同盘备份、共享目标去重和过期计划校验继续执行。

偏好和关联信息按版本写入现有本地存储，新增字段使用默认值兼容旧数据。界面升级不移动用户技能目录。旧的 Skills、工作流和环境更新入口继续可用，分阶段接入同一套交互组件。

## 9. 分期交付

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| P0：主页面减负 | Agent 切换器、作用范围、单列表、低频入口后移、上下文记忆 | 常用浏览与切换在主页面完成，首屏无目录配置负担 |
| P1：添加与更新闭环 | 明确默认位置、可信关联、自动预览、覆盖确认、就近导入、结果反馈 | 添加与更新无需重复选择目标，不存在按同名误关联 |
| P2：异常与恢复 | 就近问题处理、局部重试、撤销与历史恢复、跨页上下文衔接 | 用户能找到失败对象、完成修复并恢复操作 |
| 发布验收 | 自动化、真实桌面回放、尺寸缩放与任务测试 | 全部核心场景通过后替换现有交互；保留数据兼容 |

P0、P1 是首批用户可见交付的共同完成条件，不能只改布局就宣称安装交互已简化。P2 在同轮改造中完成，按顺序验收。

## 10. 验收标准

### 10.1 任务体验

以下为验收目标，不是已经测得的效果：

- 用户在 10 秒内指出当前 Agent、作用范围和添加入口。
- 默认目标明确的普通添加流程为“打开、选择、确认”三个阶段；不重复选择 Agent，不必阅读路径。
- 覆盖和共享影响在确认前可见；询问用户时能准确说明将修改哪些内容。
- 更换 Agent 后返回时，筛选与滚动位置保留，多选已清空。
- 用户能从问题条目找到处理动作，从操作结果找到撤销和后续恢复入口。
- 使用至少 3 个典型用户任务进行可用性走查；有条件时邀请 3–5 名目标用户，记录首次完成率、误选目标和需要解释的概念。

### 10.2 自动化与真实桌面

- 初次发现、仅配置目录、未发现 Agent、默认 Agent 消失、目标不唯一。
- 所有项目与指定项目切换、同名不同来源、共享目录归并、只读目录限制。
- 快速勾选引发预览竞态、预览过期、重复确认、安装中关闭、源或目标发生变化。
- 普通添加、覆盖本地修改、批量更新、外部技能导入、导入后继续添加。
- 部分扫描失败、取消后旧结果、安装成功但刷新失败、问题定位与重试。
- 撤销新增、恢复覆盖、目标再次修改、备份不可用、早期记录不可恢复。
- Windows 1024×680、1280×800、1920×1080，125%/150% DPI 等效视口和键盘操作。
- TypeScript、前端测试、Rust 测试、Clippy、构建、UTF-8 检查通过；真实 Tauri 回放无未处理异常、文字遮挡或溢出。

### 10.3 交付物

改版交互、状态与异常用例、必要接口变更、兼容说明、真实桌面截图和回放报告。体验指标通过本地走查或经明确授权的研究收集，不默认新增远程行为埋点。

## 设计依据

- Ant Design 设计模式：采用一致的组件与行为，并围绕具体任务组织界面。https://ant.design/docs/spec/overview-cn/
- NN/g Progressive Disclosure：高频任务优先展示，低频复杂选项在明确的次级入口按需呈现。https://www.nngroup.com/articles/progressive-disclosure/
